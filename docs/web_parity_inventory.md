# Web Parity Inventory

This document defines the current parity target for the browser-based Bzyai Web
UI. The machine-readable inventory lives at
`.supergoal/web-parity-inventory.json` and is generated by
`node scripts/audit-web-parity.mjs`.

## Parity Contract

The Web UI must reuse the existing React renderer and preserve renderer-visible
behavior for every contract, event, and stream channel currently exposed through
`VALID_INVOKE_CHANNELS` and `VALID_RECEIVE_CHANNELS` in
`src/ipc/preload/channels.ts`.

Electron desktop remains IPC-first. Browser Web mode uses a local loopback Node
HTTP server for invoke-style calls and an event transport such as SSE for
events and stream updates. Components should not fork into a second product UI;
they should select the runtime transport through the shared client layer.

Inherently Electron or OS-owned affordances are the only accepted parity
exceptions. They still need explicit browser-safe behavior rather than hidden
crashes or unsupported-channel errors.

## Cluster Definitions

- `shell/read`: read-only shell data such as settings, apps, chats, templates,
  providers, versions, quotas, context paths, and media lists.
- `mutations`: state-changing project, settings, prompt, theme, collection,
  media, file, and upgrade operations.
- `runtime/preview`: app process lifecycle, preview selection, app output,
  file runtime reads, and terminal operations.
- `chat/agent`: chat CRUD and streaming, proposals, help chat, plans, agent
  tool consent, todos, problems, and app blueprint flows.
- `integrations`: GitHub, Git, MCP, Vercel, Supabase, Neon, migration,
  Capacitor, visual editing, image/audio generation, telemetry, and integration
  prompt/response surfaces.
- `electron-only/system`: browser-incompatible window, dialog, shell,
  screenshot, restart/reset, session, or deep-link affordances that require an
  explicit Web replacement.
- `test-only`: channels only used by the E2E/test harness.

## Electron-Only Replacement Policy

Electron-only channels are not removed from the parity target. They get
browser-safe behavior:

| Electron affordance                       | Web replacement                                                                          |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| Window controls such as `window:minimize` | Hide or no-op controls in browser chrome; keep layout stable.                            |
| Native folder/file selection              | Browser-safe picker or typed path flow backed by local server validation.                |
| `open-external-url` and local file reveal | Server-mediated local OS action requiring explicit user intent.                          |
| Screenshot capture                        | Browser screenshot/canvas capture when available, otherwise server-side preview capture. |
| Restart/reset/session clear               | Local server lifecycle/reset endpoint plus browser reload or storage cleanup.            |
| Deep links                                | Loopback callback route bridged to the Web event stream.                                 |

Unsupported Electron-only behavior must fail closed with a visible, classified
error. It must not silently call Electron APIs from the browser bundle.

## Maintenance Gate

Run this command after changing IPC contracts, events, streams, or preload
allowlists:

```sh
node scripts/audit-web-parity.mjs
```

The script exits non-zero if a renderer-visible channel cannot be mapped to one
of the accepted clusters or if the preload allowlist shape cannot be resolved.
